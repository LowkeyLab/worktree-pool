# Domain docs

This repository uses a single-context layout:
root `GLOSSARY.md` and `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.

If these files are absent, proceed silently. Domain-modeling work creates
them lazily when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider whether it fits the existing
vocabulary; record real gaps for domain-modeling work.

## Decisions

Surface conflicts with existing ADRs explicitly, naming the ADR and
explaining why the decision should be reopened.
